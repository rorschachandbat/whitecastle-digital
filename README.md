# 姬路城 White Castle Digital

基于 **boardgame.io** 逐步实现的《姬路城》网页版与局面分析工具。

本项目先建立可核验的规则模型和网页客户端，再逐步加入复盘、候选行动评估与 AI 搜索。AI 训练必须建立在规则正确、行动可复现的基础上。

## 当前状态

已建立规则基准、框架研究文档和原生 JavaScript 规则工作台。工作台接入真实的 boardgame.io Client，可以查看开发文档、检查骨架状态并导出 JSON。

当前停在**阶段一的中间验收点**：两人版组件目录、配置编辑器、起始选牌和纯规则引擎已完成本批集成，核心独立于网页、boardgame.io 和未来训练器。目录含 55 张两人实体卡：花园 10、起始资源 9、起始行动 6、一层 9、二层 9、三层 9、敕令 3；起始行动三种设计各两份，保留独立实体 ID。

纯引擎支持确定性起始选牌、原子取放骰、个人面板、园丁部署与激活、手工可见面训练、家臣谒见、城堡骰色行动、城外选择及已实现图标的连锁执行。动作显式保存资源选择、子行动决策和收益次序，费用不足或遇到未实现效果时原状态不变。API 和配置要求见 [规则核心与配置验收](docs/engine-core.md)。

**当前不能进行完整对局。** 家臣晋升换牌及顶层槽位、影响力、轮末和完整随机开局仍未实现；尚无合法动作枚举、复盘或 AI。训练场 16 个基础版单面已录入，但 8 个实体的正反配对仍待核验，另外 2 个来源版本不明的面保持禁用。网页仍接入骨架 Client，未接入核心动作；导出的骨架状态不是对局存档。卡牌录入不表示其全部效果已可执行。

本项目独立实现规则。此前审查的 C# 项目仅用于架构研究，没有将其代码或数据复制到本仓库；来源和审查限制见 [资料与复用边界](docs/sources.md)。

## 本地使用

环境：Node.js 22.12 或以上，npm；固定 `boardgame.io@0.50.2`、`vite@8.3.8`，使用 `package-lock.json`。

```shell
npm ci
npm test
npm run check
```

`test` 使用原生 `node --test`，`check` 只检查文件结构、导入及文案键；两者均不构建项目。

配置编辑器可不经 Vite 或编译直接启动：

```shell
npm run config
# 打开 http://127.0.0.1:4174/config-editor.html
# 自定义端口：npm run config -- 4175
```

该命令只提供绑定回环地址的静态 HTTP 服务。编辑后先“校验并应用”，再保存浏览器草稿或导出 JSON；只有将导出文件替换仓库中的 `data/whitecastle-2p.json`，才会进入版本管理。已有局面绑定原配置，不能悄悄切换新数据。

下面是**供用户自行执行**的工作台启动和构建步骤，本次交付未执行：

```shell
npm run dev
# 打开命令输出的本地地址
npm run build
npm run preview
```

推荐检查：页面阶段提示、五个文档入口、框架初始化状态、JSON 下载、窄屏布局和键盘操作。工作台浏览器与生产构建仍待验证。配置编辑器已用不编译的静态服务做单牌修改验证，完整操作矩阵仍待验收。没有配置推送后自动构建，也没有发布在线站点。

配置编辑器入口为 `config-editor.html`。它可以编辑个人面板、55 张卡牌和训练场单面的结构化费用与效果，包含起始资产、敕令引用、牌背及个人牌的行布局展示，并校验、导出 `data/whitecastle-2p.json`。布局等完整配置可通过 JSON 编辑。训练场实体正反配对仍为空，不能按单面编号猜测；没有相应实体证据前应保持 `pending`。

## 开发约定

- 新增或修改代码注释时使用中文。
- 展示给玩家的文案集中放在 StringTable 中，通过键引用。
- 每批相关改动完成后同步更新 CHANGELOG，提交并推送到本项目 GitHub 仓库。
- 主要模块在自身目录维护 `CHANGELOG.md`，记录该模块的行为变化和验证重点。
- 未经用户在当前请求中明确要求，不运行编译或构建；改动后给出推荐验证步骤和实际已完成的检查。
- 工具脚本使用相对路径和可配置参数，不绑定某个分支或本机绝对路径。
