## 导入边界

原始捕获与私人对局只保存到 `.local/`。完整网页日志包含未来信息及撤销，不能直接作为策略特征或模仿标签。观察档案与可执行本地存档分开：只有通过合法动作及逐步状态对账，才可以标记为可继续操作或用于训练；缺少行动上下文、未公开补牌顺序或撤销目标时必须保留缺失状态。

用户后续告知取得BGA同意，现有独立[玩家回放原始库采集器](bga-crawl.md)，能保存服务端初始局面及结构化通知包。其 `whitecastle-bga-raw-replay` 格式与本页的DOM观察档案不同；采集成功仍不代表动作链已映射、可续玩或可训练。

## 使用

读取器 [bgaDom.js](../src/integrations/bgaDom.js) 导出 `captureBgaDocument(root)`，由已授权浏览器在回放iframe的body上只读调用。读取结果需等当前动作的资源计数、棋子动画和标题稳定后保存，游标改变本身不代表动画结束。

导入请求为：

```json
{
  "source": {
    "table": "桌号",
    "siteVersion": "261105-1800",
    "gameAssetVersion": "260825-0951"
  },
  "seatMap": { "平台玩家甲": "0", "平台玩家乙": "1" },
  "observation": { "format": "whitecastle-bga-observation", "version": 1 }
}
```

示例仅展示外层协议，`observation` 还必须包含读取器生成的完整公开字段。路径相对调用目录，脚本从自身位置找同分支目录与字典：

```powershell
node scripts/import-bga-replay.mjs .local/request.json .local/replay.json .local/prefinal-observation.json
npm run play
```

第三个参数可省略；提供时必须是同局最后动作完成、最终计分尚未开始的观察。导入器确认计分前后资源/人员位置一致，再从计分前累计家族分独立计算总分，避免对终局显示分二次加分。已有输出拒绝覆盖。

服务启动后打开 `http://127.0.0.1:4176/bga-replay.html`，选择输出档案。页面本机读取文件，展示资源、目录ID、训练面、计分对账与可展开历史；不把文件传到BGA。现有 `play.html` 的本地练习存档格式保持独立。
