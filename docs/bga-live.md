# BGA实时盘面侧栏

读取正在玩的公开盘面：资源、页面分数、骰子及所在位置、卡牌、人员、训练板块、BGA行动提示。持续训练主模型的冠军分析两人起始选牌、三轮普通放骰，并为首选行动逐步推演园丁目的地、资源分配、执行/跳过及效果顺序。实时园丁、武士、资源子选择只在放骰前快照、当前公开状态和可见目标唯一匹配后分析；**没有接入BGA选牌微调模型**。轮末、未匹配的行动栈和未知补牌之后暂不分析。没有跨回合搜索、自动点击或动作胜率。

## 打开与首次连接

1. 双击仓库根目录的 `打开BGA侧栏.cmd`，或执行 `.\scripts\bga-live.ps1`。每次先关闭当前副本的旧 BGA 侧栏服务，包括其他端口的实例，再从4180开始检查10个候选端口（跳过4190），启动新版并验证新进程、项目目录和协议6后打开实际地址。AI训练、本地练习及其他副本不会关闭；无关程序占用4180时自动顺延。也可在终端运行 `npm run bga:live` 后打开 `http://127.0.0.1:4180/`，此入口要求端口空闲。不需要编译。
2. 在Chrome打开 `chrome://extensions`，或在Edge打开 `edge://extensions`。开启开发者模式，选择“加载已解压的扩展程序”，选中侧栏显示的 `browser-extension/bga-live` 文件夹。此扩展是本项目源码，没有商店下载步骤。
3. 从侧栏复制实际服务地址和本次配对码，在同一个Chrome/Edge中打开实际BGA对局。点击“姬路城 · 盘面读取”扩展，填写地址、粘贴配对码并点击“开始读取当前对局”。
4. 把本地侧栏放在棋盘旁。扩展每秒检查一次DOM，连续两次相同后发送；侧栏显示最近收到时间、桌号和更新次数。BGA页面隐藏的元素和回放日志不采集。
5. 停止时在扩展点击“停止读取”；刷新BGA或换桌后重新点击开始。关浏览器或重启本机服务后重新配对。

现有ChatGPT内置浏览器不能直接加载这个Chrome/Edge扩展；实际玩游戏时使用装好扩展的浏览器。BGA现有登录会话照常使用，无需导出Cookie，也不用将密码交给本地工具。若网站显示访问上限或错误，工具不能读取缺失的棋盘。

从旧版升级：扩展0.2.1包含可见子选择采样及地址恢复，必须在扩展管理页点击重新加载，刷新BGA，再开始读取。无需卸载重装。重新执行启动器，用新侧栏的实际服务地址与配对码配对；启动器每次重启本副本的服务以加载最新代码。本次模型选择仅修改本机服务及侧栏，不需要重新加载扩展文件。进入侧栏后若处于历史快照模式，先点“返回实时盘面”。

连接成功后，扩展长期记住本机地址，当前浏览器会话仍可恢复配对码；浏览器重启后只恢复地址，需重新粘贴配对码。首次升级也需成功连接一次才会保存。`127.0.0.1`始终是本机地址，4180/4192等数字是端口。关闭侧栏网页不会关闭后台服务；重复双击启动器会重启当前副本的服务，并生成新配对码，需要在扩展中重新开始读取。无需为旧地址重启电脑；重启会停止本机训练与侧栏，之后需分别恢复训练、运行侧栏启动器并重新配对，端口如有变化以新页面为准。

“分析导出的盘面 JSON”可以导入 `whitecastle-bga-live-snapshot` 文件。接收端重新清洗观察和映射，忽略文件附带的旧建议、引擎状态及训练标志。页面明确显示原采样时间与“历史快照分析”，不伪造实时心跳。点击“返回实时盘面”后再连接扩展。导入分析结果保留在当前服务内存，刷新网页仍可查看，服务关闭后清空。

## 主模型与建议边界

`data/bga-live-ai.json` 配置默认持续训练目录、可选Python路径和推理超时。侧栏可在当前副本发现的 `continuous-rN` 中选择 r4、r5、r6；每次分析从所选目录的 `loop-state.json` 读取冠军指针，只在此目录加载对应冠军检查点。旧摆设版本会明确标为对照，不会静默当作当前规则模型。不会切换到 `bga-runs` 或最新未晋级候选，也不会改写模型、冠军指针和训练状态。Python默认取本副本 `.local/ai-venv`，路径均相对项目。

主模型复用训练时的 `TrainingEnvironment`、2345维公开盘面及160维候选，目录、启发式及编码指纹必须匹配。旧版模型对照只放宽摆设版本 `setupVersion`，并显示旧规则训练提示；不改变公开盘面合法性。冠军指针可以指向 `initial/imitation.pt` 或 `generation-*/candidate.pt`，每次分析的全部后续步骤固定使用同一个检查点。没有扩大或重新初始化网络，没有改变持续训练文件的编码指纹。只输出策略头权重；价值头不传到页面。

侧栏的“分析使用的 AI 模型”会显示当前副本可用版本、冠军代数及旧规则标记，缺少检查点或不兼容版本不能选。切换后重新分析当前实时观察和已导入的历史快照，旧任务不能覆盖新模型结果；浏览器记住选择，训练进度也跟随所选版本。故障处同时显示具体诊断代码。旧 Node 服务可能仍缓存修改前的目录及编码；更新文件后再运行启动器即可重启当前副本的全部侧栏实例并加载新代码。

起始选牌要求九骰仍在桥上、双方全部人员在个人板、零进度、影响力零位、已知先后顺序、完整花园/城堡/大名/训练区和稳定可见配对。两排牌以可见坐标核对配对，换行或动画不靠DOM顺序猜。第二人选牌时，前一人资源、资源牌背和法令必须唯一确定其已选设计并与本地收益一致，否则暂缓。剩余组合按当前可见列从左到右规范排列，已选组合放最后；不依赖原选牌列号，不读取历史或未来牌面。未知补牌只补齐目录数量，选牌输入不读取其顺序，也不向玩家提供基于补牌试走的续行。

页面标明建议对应的玩家、冠军代数、组合、起始收益和灯笼收益；起始选牌阶段的任选资源分配尚未接入。策略百分比只是模型偏好，没有MCTS和BGA棋力校准。盘面停止或超过6秒未更新时隐藏建议；异步结果必须仍对应同一桌、同一观察，不能覆盖新手。主模型训练进度每10秒读取一次，只显示本地选模评估，不能解释为当前BGA胜率。

普通放骰要求中文BGA标题明确处于桥骰选择根节点，支持第一、二、三轮及非零影响力。具名行动者与本轮已放骰数量必须一致，本人“你必须……”标题使用白鹭顺序及本轮骰数确认行动者。还原双方已用回合、人员、公开当前牌/牌背、桥端点、所有已放骰和完整摆设，城外格兼容真实的outside-the-walls-1/2，个人格兼容action-space-player-玩家ID-1/2/3（家臣/园丁/武士），大名槽按公开1/2/3对应。未知行动格或孤骰端点拒绝。后续轮次finalOrder来自白鹭顺序；未记录的历史时间轨到达优先关系对两种可能平均，并在页面标明不确定性，不能当作精确重放。

放骰前展示前五项排序及首选行动的后续路线。每一步均调用同一冠军策略，包括园丁花园、逐单位任选资源、武士训练面顺序、执行或跳过字段。路线是条件建议，玩家改选其他操作后不能继续当作当前提示。Python在一次分析中只加载一次冠军，通过JSON行协议分析后续步骤，总推理超时仍受配置约束。

服务另保存最近一次核验通过的放骰前快照与当时已知牌面。新版扩展只采集可见DOM按钮、图标和目标，不读取运行时行动栈。子选择按真实骰子移动定位根行动，在有界试走中核对双方资源、影响力、人员分布、当前牌、城堡牌和目标；有多种未解路径、超时、未采样根节点或涉及未知揭牌时显示限制，不沿用旧预测。当前只接通实时园丁、武士及尚未点选的资源提示；玩家已经在BGA本地选择部分资源时需参考完整路线，或点击资源重置后重新分析。未观察到的中途印章兑换历史暂不推断。

主模型的v2编码在放骰阶段仍读取三组起始牌，因此服务按桌保存已见公开事实到忽略目录 `.local/bga-live/contexts/`。从选牌阶段开始读取；重连会继续使用同桌历史。已选资源牌仍需由开局收益唯一核对。旧采样缺少几何配对时，只在之后公开归属使剩余各组唯一对应时补齐；历史文件不能使用晚于它的新增事实，只能重建当时的开局与当前公开信息。缺少横向槽位时对六种排列平均主网络策略。资源牌背不会猜正面，其他未见正面的灯笼只编码匿名牌背效果。

剩余牌堆只保留已核验计数，身份替换为未知标记。合法性试走到将揭未知补牌的晋升选择时停止，不把伪造补牌后的盘面交给网络，不执行跨回合推演。历史文件只复用当时可验证的开局和当前快照事实，后采样牌面不得倒灌。此模式不生成训练样本或可重放存档；持续训练编码文件和模型结构未改。

## 看什么与怎样验收

- 收到时间超过6秒标记过期，停止后保留快照但隐藏建议。换桌立即清空上一桌，旧异步分析不能覆盖新桌。
- 先用两人姬路城对局：双方金币/印章/三资源、页面分数、桥骰点数、训练场和卡牌本地ID应与页面相同。看不到的字段保留缺失，不填零。
- 在BGA正常完成一次操作后，检查侧栏资源/骰子和行动提示更新；刷新BGA应停止新采样并显示过期，再手动开始恢复。停止、换桌、关闭对局页也应正确标记。
- 多人可以显示原始资源等数据，两人目录映射明确不可用；资产版本未读到或不同于字典支持版本时，不猜测牌面身份。
- 实际对局没有回放游标时保留 `cursor: null`；不伪造回放步数，原回放导入器的严格校验保持默认。
- 在选牌阶段核对建议玩家与牌组；三轮根放骰应显示骰子端点、具体目标和首选路线。在放骰前开始读取，再进入园丁、武士或资源选择，检查目标与实际可选项相同；修改操作、补牌或缺失上下文时应重新核验或显示具体限制。

点击“导出当前观察”生成 `whitecastle-bga-live-snapshot`，包含公开快照、映射结果和问题。它仍是 `trainingEligible: false`，不能传给本地存档模型分析入口；动作上下文与规则对账仍需补齐。终局或未来信息不得回填到当时的策略输入。

## 本机连接与迁移

服务仅监听 `127.0.0.1`，每次启动产生新的配对码，写入和离线分析请求必须带配对码；普通网页来源不能读取配置或写入观察。扩展只申请当前标签页临时授权与本机地址访问，不申请BGA的长期全站权限，不读取Cookie、账号设置、聊天、网页全局变量或隐藏牌堆。实时状态与离线分析结果保留在内存；过去公开的选牌上下文保存在本机忽略目录，手动导出的私人文件也应保存 `.local/`。

端口可用 `.\scripts\bga-live.ps1 -Port 4182` 配置，扩展地址同步填写。复制到其他同布局分支时需一起保留根启动器、`scripts/`、`src/integrations/`、`src/engine/`、`src/data/`、`src/ai/`、`src/ui/`、`data/`、HTML和整个扩展目录；不依赖dist、固定盘符或分支名。读取盘面只需Node.js；主模型推理另外需要安装 `requirements-ai.txt` 的Python环境及同配置冠军权重。Python环境不能直接假定跨机器可搬，需按目标机器配置。浏览器需要重新加载目标分支的扩展。
