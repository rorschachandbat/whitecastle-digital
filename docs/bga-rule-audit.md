## 一个复杂回合的实际引擎核对

1. 白5左取，放一层右房间；先执行浅色字段，再执行付印章的武士字段。
2. 灯笼、第一次水井和房间收益补足资源；2印章换1铁，进入3铁训练区。
3. 训练面触发个人武士排，取得2珍珠母，再执行起始家臣行动。
4. 家臣谒见并晋升一层，取得一层右房间牌；浅色入场奖励再次触发水井。

共执行22个本地分阶段选择，只消耗1颗骰子。最终食物5、铁0、珍珠母2、金币7、印章1、累计分0；1名武士在3铁区、1名家臣在一层右房间。双方全部资源、人员、当前牌、灯笼牌、补牌及桥上剩余骰子与回合确认前证据一致。

回放核对显式提供了这次实际揭示的补牌，仅用于离线状态对账；没有把未来牌堆作为策略输入，也没有导出训练标签。原始资料、转录、执行脚本和断言报告仅保存在 `.local/research/`。

同一开局下，现有攻略教师选择另一房间，部署一个园丁，并为花园的后续行动付费后放弃第二次部署；回合末食物0、铁2、珍珠母0、金币1、印章0，尚无家臣或武士。这个案例说明教师能错过合法的长连锁，不能据单回合断言整局最优。

读取r8状态时，第0代已完成32局自我对弈，记录40个学习席位，平均19.175分、最高33分。查看器统计的是学习席位；同日志中对手出现36分，另有选模评估自身39分。当前奖励为自身终局分数/80且不封顶，本地计分器也成功复算了123分，因此33不是分数上限。

已经证实的弱点是预热教师本身平均仅19.47分，缺少家臣、武士及连锁组合。当前完整真人回放尚未进入三轮训练，原有BGA微调只覆盖起始选牌。当前r8又从全新本地教师预热启动。

当前搜索只提名3条路线，最多40次决策、4次放骰，后续主要由同一攻略启发式选择，截断按已提交局面计分。这可能放大短期偏好，但本次未做搜索预算/教师策略消融，不能把其贡献当作已确定结论。局部链22次选择也说明“40次决策”不等于向后看40个完整回合。

## 重复执行与边界

无需编译。在仓库根目录执行，输出文件必须是本副本 `.local/` 下尚不存在的文件：

```powershell
node scripts/audit-bga-replays.mjs --out .local/research/bga-audit-new.json
node --test tests/bgaAudit.test.js tests/bgaReplay.test.js tests/bgaTraining.test.js
node scripts/check-project.mjs
```

可传 `--database`、`--players`（逗号分隔的玩家数字ID）、`--catalog`。默认从脚本位置找到当前副本；先验证清单身份、桌号、压缩原始文件SHA-256，再解析，不下载新回放，不读取Cookie，不改动训练进程。

跨分支复制需保留 `scripts/`、`src/`、`data/` 的相同布局，另行提供该副本的 `.local/bga-database` 及可运行Node；不依赖构建目录。原始数据、账号、桌号与明细报告不提交。新的目录版本或未知通知会被拒绝或列为问题。
