# 两人规则核心第一批与配置验收

## 当前交付，不等于完整阶段一完成

本批停在“纯规则引擎第一批核心 + 可编辑数据”的验收点，不越过到合法动作枚举、网页棋盘、Yucata 复盘或 AI。完整引擎仍需补齐卡牌、人员行动、影响力和轮末。

规则依据是 [RULES.md](RULES.md)；具体数据证据与缺失清单见 [data-audit.md](data-audit.md)。只实现两人，不录入三、四人专属牌。未核验内容不能用 C# 数据或测试夹具替代。

## 模块边界

```text
data/whitecastle-2p.json ← 可视化配置编辑器 / 人工核验
           ↓
src/data/catalog.js：结构校验、规范化序列化、SHA-256
           ↓ 显式传入 config
src/engine/engine.js：纯状态转移、计分
           ↓ 后续适配（本批未实现）
合法动作模型 → boardgame.io / 网页 / Yucata 复盘 / AI 搜索
```

- 引擎不读取文件、不访问网络、DOM 或训练框架。
- 配置中存稳定 ID 与结构化费用/效果，不用中文说明文本做规则判断。
- 当前目录包含 10 张花园、16 个训练单面、3 排个人面板。8 个训练实体只有待核验占位 ID，正反关系为空。
- 编辑器是自行绘制的文字/数值预览，不分发第三方卡牌原图。
- 开放组件数据编辑不等于开放基础规则：两人、每轮每人 3 次、比较值及资源上限不随卡牌编辑变化。
- 引擎状态保存完整配置规范化签名 `configSignature`；编辑器另外展示 SHA-256 指纹。两者不是同一字段。
- 已有状态只能用创建时配置继续 `applyAction`/`score`，否则 `CONFIG_MISMATCH`。编辑数据后需新建实验，不迁移旧局面。
- 未来训练记录需同时保存配置快照、指纹、引擎版本和种子。训练器不应维护另一份卡牌表。

## API

| 接口 | 当前行为 |
|---|---|
| `createPosition(config, { seed })` | 建立两人 `core-incomplete` 实验状态；同种子同配置可复现三色九骰 |
| `applyAction(state, action, config)` | 返回新状态；非法动作抛带稳定 `code` 的 `EngineError`，原状态不变 |
| `score(state, config)` | 返回各项小计、缺失资料和 `complete`；缺失资料不猜赢家 |
| `replaceCurrentCardWithLantern(player, nextCard)` | 不可变换牌 helper，不是可任意调用的玩家动作，也不代表完整家臣行动 |

原子取放骰动作形状：

```json
{
  "type": "placeDie",
  "actor": "0",
  "bridgeId": "coral",
  "side": "left",
  "target": { "area": "personal", "row": "courtier" },
  "choices": []
}
```

`bridgeId` 必须对应状态中实际桥 ID；`choices` 按效果顺序逐个指定 `food`、`iron` 或 `pearl`。该示例只说明接口形状，不保证当前目录能执行：目录尚缺起始行动牌，直接个人面板放骰会明确拒绝。

印章兑换：

```json
{ "type": "exchangeSeal", "actor": "0", "amount": 2, "resource": "iron" }
```

`amount=1` 得金币，`amount=2` 得指定资源；仅当前玩家可用，不消耗正常放骰次数。本批不表示已经支持连锁决策中的任意时点插入兑换。

## 已支持与限制

- 取放骰整体原子执行：先支付差额，再结算左端灯笼，再区域收益（R-DIE-02/04）。
- 个人排骰色、比较值 6、容量 1，可见收益后执行当前牌对应字段；只处理固定收益、灯笼和显式任选资源（R-AREA-04）。
- 水井比较值 1、容量不限；水井资源板块尚未录入正式目录，测试必须显式使用 `setup.fixtureVersion=well-rewards-v1` 和 `wellRewards`，另加固定 1 印章（R-AREA-03）。夹具不是官方组件。
- 金币、资源、印章、分数及配置可验证的部分终局计分；时间轨/训练系数缺失时标记不完整（R-SCORE-01/02）。
- 桥剩唯一骰时，默认端点策略为空，拒绝动作而非猜灯笼；该项需继续核验。
- 城堡/城外放置容量有边界检查，**实际区域行动未实现**。
- 第 6 次放骰后停在 `round-end`，不跳过轮末花园、不自动重掷或进入下一轮。
- 当前目录无法生成正式完整开局，测试中的 `fixture-*` 牌也不是官方牌。
- 尚无 `getLegalActions`、完整存档导入、Observation 过滤或训练接口。当前状态不得作为对外玩家视角发布。

## 本批验收

不编译的检查：

```shell
npm run check
npm test
node --test tests/engine.test.js
npm run config
```

建议人工步骤：

1. 打开配置编辑器，核对家臣/园丁/武士对应珊瑚/黑/白，以及第 3、5 格混合奖励。
2. 选择 `garden-26`，把食物费用 5 改为 6，点击“校验并应用”，预览应变化；指纹应更新。
3. 保存浏览器草稿、刷新、恢复草稿；导出并重新导入，确认数据一致。未导出的页面修改不会写回仓库。
4. 尝试负费用、重复 ID、缺失来源、重复训练面或把两个蓝面组成实体，校验应拒绝。
5. 恢复默认，确认训练实体没有猜测配对，不存在“直接开始完整对局”入口。

已有单牌编辑浏览器验证不代替以上完整矩阵。未执行编译或 Vite；如用户要验证生产构建，可自行 `npm run build`、`npm run preview`，或明确授权后再执行。
