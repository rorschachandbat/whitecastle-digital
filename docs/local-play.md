# 本地双人试玩与验收

日期：2026-11-11。当前交付目标是同一台电脑上双人轮流操作、能够完成三轮并计分的练习版本，模式标识 `local-practice-v1`。

## 启动

在仓库根目录执行：

```shell
npm ci
npm run play
# 浏览器打开 http://127.0.0.1:4176/play.html
# 自定义端口：npm run play -- 4177
```

`play` 运行 Node HTTP 服务和 Node 中的 boardgame.io Client；浏览器直接加载原生 ES modules。该命令不调用 Vite、不编译、不构建，服务只绑定本机回环地址。两名玩家可以共用一个页面轮流操作，也可以在页面确认后把另一席交给冠军模型。当前没有联网多人。

## 与冠军AI对打

同一 `npm run play` 页面可以继续双人练习。若要人机：

1. 右侧“选择AI对手”选择r4/r5/r6等本机已发现版本，再确认自己扮演玩家1或玩家2。列表标出旧摆设训练、当前规则、代数或模仿预热；缺失检查点的版本不能确认。确认后固定该检查点，关闭AI后才可改选。当前r6在持续训练期间可能仍显示模仿预热，代数晋级后刷新列表即可看到新冠军。
2. 轮到AI时，它读取公开局面，在合法动作中按策略偏好贪心选择，再把完整动作提交给同一 boardgame.io Client。不会自动替你落子，也不会搜索对手后续变化。
3. 撤销会暂停AI，避免它立刻重下。需要时点“让AI落子”。关闭AI后恢复双人共用页面。
4. 只接受默认牌面与兼容编码。旧r4/r5仅显式放宽摆设版本用于对照，双方执行当前规则；编码、目录或启发式不匹配仍拒绝。支持已完成预热的initial/imitation.pt，无须等候选晋级。

策略权重不是胜率，也不是最优解。练习规则限制仍然有效。训练进程可以继续运行；对打只读取已写好的冠军检查点，不改训练文件。新开一局才会读取当时的新冠军。另一分支使用时需保留 `scripts/play-ai.mjs`、`scripts/infer-live.py`、`src/ai/playOpponent.js` 和 `data/bga-live-ai.json`；Python 环境与权重在目标机器的 `.local/` 中准备，不随仓库复制。

## 一局如何操作

1. 使用随机种子创建新局，也可以输入种子复现；同配置、同种子和同动作记录可复现。
2. 先查看本局城堡、桥骰、花园和训练场布局，点击确认后再按第一轮逆序从三组候选中选择起始资源与行动牌，完成必要的任选资源选择。选牌阶段可以回看同一布局。
3. 当前玩家选择桥端骰子、合法放置区，再由行动向导逐步选择资源、人员、晋升目标、卡牌字段和可选执行顺序；确认后提交完整动作。
4. 每轮两人各放三骰后进入轮末。第一二轮更新全体顺序，逐名处理合格花园；随后清除已放骰并重掷桥骰，保留所有人员与卡牌。
5. 第三轮结束更新最终顺序并计分，不执行花园；同分时最终顺序靠前者胜。

界面提供撤销、JSON导出和导入。浏览器在每次完整动作后自动保存；导出存档保存配置快照、种子及动作记录，导入时由引擎重放，不信任文件中附带的任意局面。

## 卡牌配置

同一服务提供 `config-editor.html`。在配置编辑器修改后校验并导出JSON，在**新开局**加载该配置。已开始的局面继续绑定其配置快照，不能静默使用后来修改的卡牌数值。

55张两人实体卡、起始行动三种各2张、金/银训练池各8面及固定个人面板来自已核验目录。训练场按用户确认版本从金银两池各无放回抽2个；1铁区金、3铁区银、5铁区金银各1。额外1金1银图面归属不明，继续禁用，不参与抽样。此前要求金银正反配对的推断已经撤销。

## 当前练习配置

以下参数在存档配置中明确保存；它们用于让本地对局连贯运行，不能被当作已经完成全部一手核验的正式随机设置。

| 项目 | 本地行为 | 核验状态 |
|---|---|---|
| 城堡比较值 | 一层3、二层4；城外5 | 已由出版方主棋盘图核验 |
| 城堡骰色 | 红黑白各5块，无放回抽13块城堡、2块水井；房间至少两色 | 已按用户确认修正库存；实体编号及资源背面映射仍未核验 |
| 水井 | 比较值1、获得印章1＋食物1＋铁1 | 比较值及印章来源明确；两块资源板固定为练习夹具，尚未复现正式板块抽样 |
| 时间轨格值 | 起点0、终点20；进入6/11/15格支付1/2/3印章；15–20格值10–15分 | 已由出版方主棋盘图核验，第二/三季分别3/6分 |
| 影响力拒付 | 已移动到关卡前；拒付或付不起时停下，丢弃此次剩余步数 | 显式练习约定，原规则文字未明确整笔移动中的部分处理，仍属U-05 |

| 桥上最后一骰 | 留在原端点；中段有骰时才向新空端补位 | 按原规则的补位条件及桥两端结构保留，不自动归左 |

卡牌、训练池和时间轨的核验记录分别见 [数据核验](data-audit.md)、[训练池核验](training-pairing.md) 与 [规则基准](RULES.md)。本地练习可用来发现资源、费用、连锁、换牌和轮末实现问题；尚不适合据此声称找到了正式规则下的最优路线。

## 建议验收

- 新开局确认资源牌9、行动实体6，并检查两名玩家逆序选牌。
- 左端取骰时先支付放置差额再结算灯笼；失败动作不得留下扣费或取骰。
- 黑骰对应园丁排、白骰对应武士排；部署后揭开奖励与人员数量一致。
- 家臣进入一二层时检查旧牌进灯笼、新牌成为唯一当前牌、房间补牌；牌堆空时仍获得浅色行动。
- 登顶检查先灯笼再空槽恩赏；槽满仍可晋升并获得灯笼。
- 第一二轮只触发仍有桥骰对应花园，每个已列出的合格花园最多触发一次；第三轮不触发花园。轮末连锁新部署人员的后续资格仍应通过具体规则案例另行核对。
- 完成一局共18次常规放骰，检查分项计分、武士乘数及最终顺序破同分。
- 导出、撤销、重新导入，检查资源、卡牌、人员、轮数和最终结果一致；修改JSON配置后新建局面测试生效。

本说明不代替实际验证报告。Node测试、浏览器试玩及未执行的编译/生产构建须在本批CHANGELOG和交付说明中分别记录。
