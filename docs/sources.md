## 1. 规则来源

- 用户指定规则：[Yucata《姬路城》](https://www.yucata.de/zh/Rules/WhiteCastle#diceget)。
- 对照入口：[同站英文规则](https://www.yucata.de/en/Rules/WhiteCastle)。
- 用户指定样本：[房间 #17166497](https://www.yucata.de/zh/Game/WhiteCastle/17166497)。

整理后的项目准则是 [RULES.md](RULES.md)。其中注明了来源顺序、规则编号、验收案例及待确认项。规则入口虽为中文，本次读取的详细正文为英文。

本文和规则文档以独立表述整理机制，没有复制整份规则书、卡牌插画或第三方美术。完整卡牌、个人面板、时间轨和布局数据仍需按规则文档逐项核验；不要将未核实数据当作完整基础版。

## 2. C# 参考项目

来源：[bojanspasic/boardgame-white-castle-digital](https://github.com/bojanspasic/boardgame-white-castle-digital)。

本次克隆并静态审查提交：`1ef222bf71e84bd3b3654a45306235e3871f6b70`。

它是 C# 引擎和终端客户端，不是可直接接入的 boardgame.io 网页。值得研究的是独立引擎、合法动作生成器和动作处理器的模块划分，不能直接将其实现作为训练环境。

静态审查发现的关键差异：

| 项目 | 参考代码中的行为 | 本项目规则依据 |
|---|---|---|
| 当前个人行动牌 | 累积多张个人牌，并持续激活起始牌 | R-COURTIER-02：只有一张当前牌，旧牌进入灯笼区 |
| 换轮 | 重置训练场，清除已放武士 | R-BASE-03、R-ROUND-03：人员与训练场板块保留 |
| 终局资源 | 至少 4 个才得 1 分 | R-SCORE-01：3–6 个得 1 分，7 个得 2 分 |
| 金币与印章 | 分开除以 5 | R-SCORE-01：合并后每 5 个得 1 分 |
| 个人面板 | 黑、白骰对应人员交换 | R-AREA-04：黑色园丁，白色武士 |
| 左端骰 | 取骰后立即给灯笼收益 | R-DIE-04：先放骰并支付差额，再结算灯笼 |
| 灯笼 | 额外加分、忽略影响力收益 | R-LANTERN-01：只执行灯笼区实际收益 |
| 合法动作 | 可生成印章不足的支付动作、免费 Pass | R-DIE-05、T-20：动作合法且失败原子性 |

这是源码与规则的静态比较，不是已运行第三方测试的结论，也不是完整缺陷清单。完整卡牌尚未逐张审查。

研究时未找到明确 LICENSE，GitHub 元数据的 license 字段为空。因此本仓库**不复制该项目的代码或牌数据**，而是依据规则独立实现。参考克隆和审查工作文件保留在用户仓库以外。

## 4. Yucata 数据边界

已观察到公开 client-data 可包含当前局面和动作日志；动作载荷同时存在 `P/E/A` 与 `ActionParams/ActionEffects/Automatic` 字段形式。动作效果不等于完整状态补丁，单条日志也不等于一次完整玩家回合。

这些观察仅用于后续只读适配设计。当前没有实现局面导入、完整历史还原或向线上房间提交动作；也没有将 Yucata 作为搜索分支的执行后端。

原始房间 JSON 可能含玩家资料，未提交到本仓库。以后添加测试夹具时只保留验证所需字段，移除账号、聊天、凭据等信息。不能将公开可读理解为获准再分发全部代码、素材或对局资料。
