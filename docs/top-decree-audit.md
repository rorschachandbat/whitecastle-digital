## 大名槽位及连锁规则

现有 `docs/RULES.md` 的 `R-COURTIER-03` 与来源 P8 一致：

1. 家臣实际到达三层，先结算该玩家完整灯笼收益。
2. 若本局大名卡有空槽，选择**任意一个空槽**，家臣占住它并获得该槽收益。
3. 三个槽是全体玩家共享的占位，不是每名玩家各有三个。
4. 所有槽都满时，家臣仍可到达三层，并照常获得先前的灯笼收益；该家臣保留在三层，只是不再拿槽奖励。
5. 奖励为园丁、个人面板或水井行动时，继续执行对应行动的正常规则。没有印刷额外费用，不意味着免除园丁部署食物等该行动自身费用。
6. 个人面板行动按图标规则视为点数 6 的虚拟行激活，不放实体骰；同一常规回合不能用该图标重复激活同一排。
7. 水井行动不放实体骰，不凭空产生骰子比较差额；获得正常水井收益。
8. 每名三层家臣的终局 10 分属于三层位置计分，不能再编码成卡槽固定奖励或按人数乘数。

三槽之间是**互斥选择**，不是可任意排序全部执行的效果组。同一个槽内本批每张图只有一个奖励条目，暂不涉及组内排序。

相关规则：

- 不是开局自动把三个收益都发给每名玩家。
- 起始资源卡明确授予某张法令时，取所指法令并直接放入灯笼区。
- 法令的图标作为灯笼区可见收益，随正常灯笼触发重复生效。
- 法令没有可执行的三行正面个人行动；不要将其作为 `currentCard`。
- 法令的收益不附带按人员数量计算的条件或倍率。
- 取得法令当下不等同于触发一次灯笼；资源卡若还授予立即收益，应分别编码。

当前目录的稳定 ID 为 `decree-points`、`decree-seal`、`decree-coin`，以图片图标匹配资源卡的 `grantDecreeId`。不能只按文件排序推断资源卡与法令的编号对应。

## 当前结构化数据

以下为当前目录 `top-1` 的核心结构摘录，省略来源、核验状态和适用人数：

```json
{
  "id": "top-1",
  "kind": "top",
  "fields": [
    {
      "id": "left",
      "tone": "none",
      "capacity": 1,
      "cost": [],
      "effects": [{ "type": "gardener", "amount": 1 }]
    },
    {
      "id": "middle",
      "tone": "none",
      "capacity": 1,
      "cost": [],
      "effects": [{ "type": "pearl", "amount": 2 }]
    },
    {
      "id": "right",
      "tone": "none",
      "capacity": 1,
      "cost": [],
      "effects": [{ "type": "coin", "amount": 3 }]
    }
  ],
  "selection": "oneEmptySlot",
  "back": []
}
```

已采用的结构与执行边界：

- 大名三槽已使用 `fields`，`id` 固定为 `left/middle/right`、`tone:'none'`、`capacity:1`；卡级选择方式为 `selection:'oneEmptySlot'`。奖励没有 `per` 倍率。
- 目录保存容量和奖励，不保存当前占用。未来实现家臣晋升时，仍需由局面维护共享槽位身份；当前引擎没有完成该流程，不能把目录字段当作已经可执行的三层状态机。
- 到达先灯笼的规则属于家臣移动时序，不在各大名槽位的效果数组里额外复制。
- 法令已使用 `kind:'decree'`、`fields:[]`、`orientation:'lanternOnly'`；`back:[{type,amount:1}]` 表示灯笼收益。该字段名不意味着本次观察到了隐藏的另一面，也不生成个人行动。
- 起始行动使用六条独立实体 ID：`start-action-courtier-1/2`、`start-action-warrior-1/2`、`start-action-gardener-1/2`。各记录带共同的 `designId` 和 `copy:1/2`，不是用 `copies:2` 对单条记录或效果作倍率。
- 每条起始行动实体只有一个 `action` 字段，`layoutRows` 覆盖三排，`back` 为 1 影响力；当前个人排逻辑已接入该布局。影响力结算及完整牌库开局的限制仍以引擎和规则待确认项为准。
- 图片由 `sourceRef:'image:…'` 对应 `imageSources` 的路径和 SHA-256；组件分类依据另见目录的出版方来源。项目自己的实体 ID 不等于已经核验的 Yucata 数字 ID。

## 补充：起始行动对个人面板三排的适用性

可直接观察到三种起始行动正面只有一个主行动图标；没有三排不同的行动、数字或分隔线。Yucata 个人面板规则说明，放骰后执行当前行动卡给该排的奖励；出版方 P5 同时明确这些黄色单图标卡就是起始行动卡。

据此，当前目录和引擎已将起始行动卡的一个公共字段适配到三排；这是**结合卡面和个人面板规则的解释**，不是图片中另外印着“三排通用”文字。后续线上差分用例可在相同起始行动牌下分别触发不同颜色个人排，观察是否进入同一个家臣/园丁/武士主行动。公共字段不套用到实际有三行不同效果的家臣房间牌。
