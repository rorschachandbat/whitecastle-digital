# 纯规则引擎 CHANGELOG

## 2026-11-11 — 本地三轮对局与可重放行动向导

- 新增 `localMatch.js`，组合逆序选牌、固定种子摆设、三轮18次放骰、影响力排序、轮末花园与终局；配置和训练器不依赖网页或框架。
- 金银独立池各抽2块，同池不放回，整局保留；支持手工训练摆设。时间轨使用出版方核验0–20格、6/11/15关卡及正确分值。
- 新增 `actionOptions.js`，原子试走返回字段、资源、顺序、人员和城堡选择；棋盘候选先检查费用、颜色、容量，后续仍用引擎校验。
- 存档以目录、种子和动作重放，支持撤销并忽略外部伪造状态；错误不修改输入。
- 检查：全项目110项Node测试通过，含真实Client、轨道、轮末及存档；未编译或构建。城堡色块、水井资源、拒付部分移动及轮末新园丁资格仍显式标为练习处理。

## 2026-11-11 — 家臣晋升、轮末花园和交互式选择

- 家臣行动支持谒见、一步/两步晋升、跨层直达、房间浅色行动、楼层牌堆补牌和三层大名共享槽位；无空槽时仍可到达并结算灯笼。
- 新增 `resolveGardenReward`，轮末可重复结算已部署花园的奖励，不重新部署或支付食物。
- 新增金银独立训练池模式入口并校验选中面的牌池归属；保留旧手工可见面模式。行动上下文支持交互式字段、同组效果顺序、人员目标和资源/印章兑换提示。
- `physical` 孤骰策略按本次取骰侧保存实际剩余端点；保留旧 `null`、固定左右端实验策略，避免历史测试配置被静默改写。
- 规范化放置区时省略未定义字段，确保 boardgame.io 的 JSON 边界与纯规则状态完全一致。
- 新增 `tests/courtier.test.js` 覆盖晋升、换牌、三层、轮末花园、交互式提示和原子失败。
- 对应规则：`R-COURTIER-01..03`、`R-ROUND-02`、`R-INFLUENCE-01`、`R-DIE-01`。新增14项家臣/交互回归测试通过；此前四个相关测试文件共59项通过，追加用例由主任务统一复核。未编译或构建。

## 2026-11-11 — 实体选牌、卡牌布局与区域连锁

- 新增 `cardRules.js`：起始牌公共字段、地头三排、使节明确行跨度、骰色字段和浅色字段解析；布局错误拒绝猜测。
- 新增 `startingDraft.js`：固定种子两堆各抽三实体并配对、逆序选择、初始资产及法令入灯笼、签名绑定；止于独立选牌阶段。
- `engine.js` 接入正式目录的园丁、手工训练、家臣2金币谒见、城堡同色字段和城外选择，支持个人排/城堡图标及水井实验收益的连锁。
- 所有连锁显式提供资源选择、子决策和收益次序；组合排序支持 `null` 默认项。字段放弃发生在字段收费前，人员放弃发生在已付字段费用后。图标行动没有实体骰和额外骰差收益。
- 训练评分读取已核验训练区系数；人员留场，5人上限、同花园本人重复部署与资产不足均拒绝。
- 对应规则：R-SETUP-04、R-AREA-01..04、R-WARRIOR-01、R-GARDENER-01、R-COURTIER-01、R-LANTERN-01、R-SCORE-01。全项目70项Node测试通过，语法检查通过，无编译/构建。
- 仍未完成晋升换牌、三层、影响力、轮末与正式随机设置。连锁深度当前上限8；印章兑换不能插入原子连锁。手工训练不保证真实实体抽样分布。
- 推荐验收：按 `docs/engine-core.md` 用显式实验局面检查先收益后付费、反序失败、放弃费用差异及输入不可变。

## 2026-11-11 — 两人核心状态与原子动作

- 新增不可变的 `createPosition(config, { seed })`、`applyAction(state, action, config)`、`score(state, config)`。
- 覆盖资源上限、印章兑换、三色九骰稳定生成、桥端点取骰、两人局放置容量、金币差额、左端灯笼顺序、个人排可见收益和当前行动牌置换 helper。
- `placeDie` 将桥骰选择、支付、灯笼和区域收益作为一个原子动作；付不起费用或遇到未实现效果时，骰子仍留桥且原局面不变。
- 个人面板的骰色和可见收益读取已核验目录，当前牌通过稳定牌 ID 与排字段映射取行动。只支持确定收益及显式任选资源；影响力、人员、城堡等复杂图标拒绝执行。
- 水井比较值固定 1、容量不限并额外给 1 印章；真实水井资源板块尚未核验，因此只有带 `setup.fixtureVersion=well-rewards-v1` 的显式实验收益可执行。训练场面不能替代水井板块。
- 局面保存创建时配置的规范化 `configSignature`，包括实验夹具；变更配置后不能继续动作或计分，返回 `CONFIG_MISMATCH`。
- 所有未核验的城堡、城外、训练场、花园、时间轨及卡牌数据必须由配置显式提供；缺失时返回稳定 `DATA_UNVERIFIED` 或在计分结果中标记 `complete=false`。未知终局顺序不用于猜测同分胜者。
- 动作失败不会修改原状态；不依赖 DOM、boardgame.io 或 `Math.random()`，只复用数据模块的规范化 JSON 序列化。
- 对应规则：`R-BASE-02`、`R-DIE-01` 至 `R-DIE-04`、`R-AREA-03` 至 `R-AREA-04`、`R-COURTIER-02`、`R-SEAL-01`、`R-LANTERN-01`、`R-SCORE-01` 至 `R-SCORE-02`。
- 桥只剩一骰且端点策略未核验时拒绝取骰；不会通过丢掉左右语义自动给灯笼。
- 每轮六次正常放骰后停在 `round-end`，不自动跳过花园或进入下一轮。人员数组在动作间保留。
- 检查：`node --test tests/engine.test.js`，19 个用例全部通过；`node --check src/engine/engine.js` 通过，均未触发编译。
- 推荐验证：补齐正式水井、行动牌和时间轨资料后，先增加逐条规则回归；获得编译授权后再接入页面交互验证。
- 这是第一批核心，不代表完整基础版规则已实现；未实现轮末花园、影响力、完整牌库、棋子部署和合法动作枚举。种子局面为 `core-incomplete` 实验状态，不是正式随机开局。
